## Screens and navigation

`/admin/roster` implements source tabs Calendar, Shift list, Attendance monitor, Timesheets and Attendance corrections. Calendar has day/week/month views, Today/previous/next, employee/house/status filters, shift blocks and Add shift slots. Scheduled shifts are the default; Cancelled/All are explicit choices. All grids, toolbar, blocks, colours and drawers use original `ad-` classes. Overnight shifts appear on each intersected NZ date, including the continuation in day/week views; exclusive midnight ends do not add a date. Keyboard-operable buttons provide calendar controls and month-to-day selection.

Shift list defaults to Upcoming and also offers Past/Scheduled/Cancelled/All. It has search, employee/house/status/date filters, entity links, sort, ten-row pagination and View/Edit/Cancel. Source-style drawers implement Create/Edit/Details and confirmed cancellation. Attendance defaults to Today; Timesheets has an independent date range. Attendance and Timesheets use shared scheduled shifts and their actual attendance, explicit scheduled versus actual duration, status, fictional location, issues, correction state and details. No event is invented for a shift without attendance. Employee operational tabs now link directly to these same records.

Correction queue filters pending/approved/rejected, employee/house/request-date and search. The review drawer compares original events, current effective values and proposed values, with reviewer/time/notes after a decision. Leave includes Pending/All tables, employee/current-assignment-house/type/status/period filters, conflict count, details/review and a month calendar. Calendar summaries contain employee, leave type and status; private reasons are excluded. Approved entries show by default; pending entries require an explicit checkbox and distinct textual status. Rejected entries are excluded.

Query-backed detail panels preserve Back/forward, breadcrumbs, refresh and close. Unknown/malformed IDs, repeated/unsupported/conflicting selectors and actions fail server preview validation with generic 404. Seeded IDs refresh after explicit development opt-in. Valid UUID session records lost on reload show generic unavailable panels. List filters and calendar view/anchor are local view state and reset on remount/refresh, matching the source; they are not durable saved views. Existing canonical routes are retained; no duplicate API or route hierarchy is introduced.

## Shared operations and scheduling rules

`modules/admin/workforce/adapter.ts` contains `validateShift`, `saveShift`, `cancelShift`, `reviewAttendance`, `reviewLeave`, conflict queries and management attendance presentation. Every operation checks the established Administrator/Manager preview role and an existing active management actor (`a1`/`m1`). Ordinary Staff and Senior Staff reject. Core Manager restrictions on Administrator accounts remain intact. The existing preview has one organisation and organisation-wide operational management, with no configured manager-to-house action grant; a narrower manager scope is not invented.

Shift input is explicitly allowlisted. Employee/house must exist and be active, and the current assignment must exist. A mismatch gives: “This employee is not currently assigned to the selected house.” Assignment creation is never implicit. UUID IDs, assigning actor/name, optional notes and non-negative whole break minutes are retained on the same Shift. Break information is descriptive; it is not deducted from recorded or scheduled operational durations. Only Scheduled is accepted by the editor; Cancelled requires the separate confirmation.

Dates/times continue using the existing representation: UTC ISO instants for events and shifts, date-only strings for leave, `Pacific/Auckland` for wall-clock inputs/display. End earlier than start means the following local date; equal times reject. Invalid calendar/time values and missing/ambiguous DST wall times reject using the existing converter. Overnight durations use UTC subtraction, including 7/9-hour DST nights; they never become negative. There is no arbitrary shift eligibility window, GPS radius or clock-out policy.

Employee shifts cannot overlap any other non-cancelled assignment, including another house or an overnight interval. Adjacent boundaries are allowed. Update repeats all validation. If any attendance references a shift, all schedule editing and cancellation are blocked as a conservative development policy. This preserves original employee/house/schedule associations while final historical-edit policy is undecided. Cancel otherwise changes the explicit status only; it never deletes the shift. Original IDs, related collections and historical cancelled roster visibility remain. Existing Staff eligibility/upcoming/highlight selectors exclude cancelled shifts; real Clock In/Out remain disabled.

## Original and effective attendance

`AttendanceRecord.clockIn/clockOut/location` remain original fictional events. `AttendanceCorrectionRequest` adds optional base-correction ID and a grouped decision containing reviewer, UTC decision time, notes, original event timestamps, prior effective timestamps and approved effective timestamps. Historical approved/rejected fixtures without decision metadata remain display-only; their labels do not imply a newly applied event version.

`roster/effective.ts` resolves the latest approved decision with metadata. Staff timesheet rows/totals, Admin tables/details and attendance state use effective values. Original events remain separately visible in both detail interfaces. The effective location is explicitly fictional-unverified following a manual correction; an approved correction is never presented as successful GPS verification. There is no GPS bypass or continuous tracking.

Review requires a pending request and matching original attendance, employee and shift. Approval validates a changed, valid, past effective interval; blank proposals retain current values. Rejection requires visible review notes and leaves effective values unchanged. Both retain decision metadata on the original request. No care-record correction approval was implemented.

**Mock conflict rule:** a request records the latest applied correction ID at Staff submission. Approval succeeds only if that base still matches the latest effective version. Of simultaneous pending requests, the first approval makes competing old-base requests stale; those can be rejected with a reason but cannot be approved. A new Staff request can reference the newly effective version. Duplicate decisions reject. This is deterministic session validation, not database concurrency protection. Future transactional version checks are required.

Management states derive from shared data: Not Started, In Progress, Completed, Missing Clock-in, Missing Clock-out, Correction Pending and Cancelled. Staff retains its established Not Clocked In wording and independent correction badge. Both use the same effective timestamps and missing-out rule. Scheduled hours never substitute for actual events. Recorded time is not payroll-approved time.

## Leave decisions and roster conflicts

Staff creates the same Pending Review LeaveRequest used by Admin. Review requires an existing pending request, employee/type and valid inclusive date range. Approval and rejection require explicit confirmation; rejection requires a reason. Decision reviewer/time/notes remain visible to the employee in Staff Leave. Already decided requests are read-only; repeat decisions reject.

Conflicts derive non-cancelled shifts for that employee whose NZ covered dates intersect the leave period, including overnight shifts. Detail and confirmation show the conflict count and separate roster links. **Approval never cancels, deletes, reassigns or changes a shift**, changes attendance or deducts supplied balances. Separate management follow-up is required. Staff cannot cancel approved leave. Management cancellation, pending withdrawal, partial days, accrual/entitlements and payroll integrations remain unimplemented policy areas.

## Shared propagation and dashboard

The existing root preview provider, projection and scoped merge remain the only state boundary; no Admin fixture store, browser-storage database or mock API was introduced. Staff-created requests merge into that same full dataset, and management decisions project back to the current employee. Employee identity and shift/request/attendance IDs remain stable. Tests exercise Admin create/edit/cancel → Staff roster/My Shifts, Staff correction → Admin approval → effective Staff timesheet, and Staff leave → Admin conflict review → Staff decision while the original shift remains scheduled.

Dashboard uses existing shared counts and today's shifts, now resolves the same management attendance status, reports unique scheduled employees/pending attendance corrections and links attendance requests to their actual queue record. Core totals and pending leave/correction counts update with the same snapshot. No hard-coded operational totals are added.
