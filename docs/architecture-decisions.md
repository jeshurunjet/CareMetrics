# Bootstrap decisions

1. **One active application.** Source-only zip is immutable visual evidence. Archive earlier partial migration in full before establishing the latest-export shell. No bulk migration of legacy views. Original CSS is copied byte-for-byte, with router-specific additions separate. Icons and staff chrome derive from the export; admin chrome is a limited adaptation. Neither has visual parity sign-off.
2. **Keep this checkpoint small.** App Router layouts, safe login presentation, staff/admin chrome, route placeholders and read-only fictional shifts establish the foundation. Full StaffApp/AdminApp and prototype store are not imported. No database schema inferred from browser arrays. Auth.js/Prisma/Neon/private Blob remain the approved backend stack, to be introduced in verified phases.
3. **Fail closed.** Production/test cannot enable preview even with its flag set. Server layouts and every preview page return 404 before rendering preview content. Production response-content checks caught and fixed layout-only gating. Login/recovery do not accept credentials, send email or show simulated success. No role cookie, role switch, OTP shortcut, GPS simulation or server mutation is active. This boundary is a temporary preview guard, not authentication or organisation/house permission enforcement.
4. **Modular monolith.** `src/app` composes routes; `components/layout` holds chrome; `modules/auth/ui` holds authentication presentation; `modules/workforce` holds explicitly named read-only fixtures; `lib` holds small shared helpers. As vertical slices are built, each module gets UI, service/validation and server repository boundaries. Future db/auth/files/permissions code must use `server-only`, trusted sessions and scoped queries. Do not create empty pretend services or competing domain models.
5. **Current stable frontend.** Registry resolution selected Next 16.3.8 and React/DOM 19.3.1; strict TypeScript 5.9.3 remains. Tailwind v4 uses PostCSS for Next, not Vite. Framework lint config matches Next. ESLint 9.39.5 is retained for plugin peer compatibility; registry marks it deprecated, while the config's React/import/a11y plugins do not declare ESLint 10 support. Revisit this tooling limitation before deployment. No Auth.js/Prisma compatibility claim until a provider and ORM version are selected/tested. Official setup references: [Next installation](https://nextjs.org/docs/app/getting-started/installation), [Next lint](https://nextjs.org/docs/app/api-reference/config/eslint), [Auth.js Prisma adapter](https://authjs.dev/getting-started/adapters/prisma).
6. **No deploy at bootstrap.** Vercel is the target; no project/secrets provisioning or deployment performed. Environment names are server-only and blank for future services. Preview disabled in production. Health data/privacy/residency/retention/storage policy approval remains separate.
7. **Verification isolation.** Builds explicitly use webpack because sandboxed Turbopack PostCSS workers cannot bind an IPC port. Development uses `.next-local`, builds `.next-build`, Playwright `.next-e2e`; inherited tracked `.next` artifacts are left untouched. Repository maintainers should untrack generated `.next` files in a separate cleanup. Pin Node 22 LTS tooling in mise; actual host Node 25.9.0 is recorded as a verification limitation.
