## Key, cost and privacy boundaries

The user chose the [Google Maps Demo Key](https://developers.google.com/maps/documentation/javascript/demo-key), with no billing setup. Google's [Demo Project terms](https://cloud.google.com/terms/maps-platform/demo-project-terms) limit it to evaluation/testing; this is not a production Maps configuration. Daily demo quota can suspend maps, and there is no SLA. There is no automatic paid fallback, account upgrade or billing change. The application cannot prove a Google account's billing state if its owner later changes that account externally.

The key is held in a private operator file outside the repository. The application requires `GOOGLE_MAPS_DEMO_BROWSER_KEY`, `CAREMETRICS_GOOGLE_MAPS_DEMO_ACK=no-billing-evaluation-only`, existing pinned demo-deployment settings, and the matching fictional organisation. It exposes only the intentionally public browser SDK key to the authenticated Staff page. It is not a `NEXT_PUBLIC` build constant or server secret; authorised browsers can inspect it. Auth, database and scheduler credentials remain server-only. No real key belongs in source, examples, test fixtures or academic exports.

Google receives the displayed map/location information when its SDK renders the view; the screen discloses this. The foreground samples and calculated distance stay in memory and do not become a movement history. The successful Clock In uses the existing accepted-event storage and seven-day coordinate expiry; the returned advisory is transient and is not added to policy snapshots, audit summaries or retained attendance history. The existing cleanup mechanism and database schema are unchanged. Map failure leaves coordinate/status and attendance controls available; it does not create a record or silently switch to a billable service.
